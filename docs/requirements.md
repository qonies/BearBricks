## 1. 项目概述

BearBricks 是一款浏览器端运行的现代俄罗斯方块（Tetris）对战游戏。玩家无需注册登录，输入昵称即可开始：可单人游玩、与 AI 对战，或创建/加入房间进行最多 4 人的联机对战，房间内提供轻量文字聊天。

**一句话定位**：零门槛的浏览器多人俄罗斯方块对战平台。

## 2. 目标与非目标

### 2.1 目标
- **G1 标准手感**：复刻 Tetris Guideline 核心机制（SRS 旋转 + 墙踢、7-bag、锁定延迟、Hold、Ghost、DAS/ARR）
- **G2 三种对战模式**：竞速赛（sprint）/ 生存淘汰（survival）/ 限时赛（timed），最多 4 人同房，支持 AI 混战，房主开局前选择
- **G3 零门槛**：访客身份（localStorage），无账号体系
- **G4 轻量社交**：房间内纯文本聊天 + 系统消息
- **G5 公平**：服务端权威架构，AI 与真人共用同一引擎

### 2.2 非目标（本期明确不做）
- 账号体系、注册登录、第三方登录
- 战绩/排行榜/历史对局的持久化存储（仅本地最佳成绩存 localStorage）
- 房外围观者（spectator）、录像回放
- 道具、皮肤、付费、商城
- 原生 App / 桌面客户端
- 语音聊天、表情图片消息
- 好友系统、跨房间广播
- 多语言（默认简体中文，仅预留 i18n 结构）
- 移动端触控为 **P2**（可延后，见 FR-12）

## 3. 角色与用例

| 角色 | 说明 |
|---|---|
| 访客玩家 | 无登录，localStorage 生成身份；可单人/联机 |
| 房主 | 房间创建者；拥有模式选择、补 AI、踢人、开局权限 |
| AI 机器人 | 服务端运行，与真人同规则同引擎，3 档难度 |

**用例**：
- UC-1 单人开局：大厅 → 单人模式 → 选 Marathon / Sprint 40 → 本地游玩（可暂停）
- UC-2 创建房间：选公开/私密 → 得 6 位房间码 → 分享 → 补 AI → 选模式 → 开始
- UC-3 房间码加入：输入房间码 → 进入房间 → 准备 → 等房主开局
- UC-4 快速匹配：优先加入有空位的公开房；无则自动建房
- UC-5 对战：按所选模式对战（§4.3）→ 结算排名 → 再来一局
- UC-6 聊天：房间内随时发送文本；系统消息自动播报进出/淘汰/胜负
- UC-7 断线重连：网络闪断 30s 内重连恢复座位与棋局
- UC-8 AI 补位/替换：空位补 AI；真人中途加入可替换 AI 座位（仅 WAITING）

## 4. 游戏规格

### 4.1 棋盘与通用规则（所有模式共用）
- 棋盘 **10 列 × 20 行可见 + 2 行隐藏缓冲**（共 22 行；**数组索引自上而下 0~21**，0~1 为隐藏缓冲区；协议快照 board/active 同为 top-down）
- 方块出生位置在隐藏缓冲区（数组 index 0），居中出生；**出生后若可下移则立即下移一格**（Guideline，保证底行进入可见区）
- **旋转系统**：SRS，含标准 I 块与 JLSTZ 块踢墙表
- **随机**：7-bag 洗牌算法，RNG 使用服务器下发的 seed（xorshift128，确定性可复现）
- **Hold**：每块锁定前最多 1 次
- **预览**：Next 队列可见 5 块
- **Ghost**：落点投影（可在设置中关闭）
- **输入**：DAS = 133ms、ARR = 33ms（客户端可在设置调节）；软降速度 = 重力 ×20；硬降立即锁定
- **锁定延迟**：500ms，移动/旋转最多重置 **15 次**，超时强制锁定
- **顶出判定**：
  - *Block Out*：新块出生位置被占用
  - *Lock Out*：方块完全锁在可见区之上（即隐藏缓冲区，自下而上第 20 行及以上）
- **重力**（Guideline 公式）：`秒/行 = (0.8 − (等级−1)×0.007)^(等级−1)`，每消 10 行升 1 级

### 4.2 计分表（Marathon / timed 使用）
| 动作 | 分数 | 动作 | 分数 |
|---|---|---|---|
| Single | 100 × 等级 | T-Spin Mini（无消行）| 100 × 等级 |
| Double | 300 × 等级 | T-Spin Mini Single | 200 × 等级 |
| Triple | 500 × 等级 | T-Spin Single | 800 × 等级 |
| Tetris | 800 × 等级 | T-Spin（无消行）| 400 × 等级 |
| 软降 | +1 / 格 | T-Spin Double | 1200 × 等级 |
| 硬降 | +2 / 格 | T-Spin Triple | 1600 × 等级 |
| — | — | Perfect Clear | +3500（不乘等级） |

- **B2B**（Back-to-Back）：连续 Tetris / T-Spin 消行，分数 ×1.5（向下取整）
- **Combo**：连续锁定均有消行，第 n 连额外 `50 × (n−1) × 等级`（首消无加成，n 从 1 起）
- T-Spin 判定：T 块最后动作为旋转且四角占据 ≥3（场外含上方一律视为占据；含踢墙规则细分 Mini）
- 注：T-Spin Mini Double 在 SRS 几何上不可达（mini 踢法无法构成双消），故表中不列、引擎计 0 分

### 4.3 攻击与垃圾行（survival / timed 启用，sprint 关闭）
| 消行结果 | 攻击行数 |
|---|---|
| Single | 0 |
| Double | 1 |
| Triple | 2 |
| Tetris | 4 |
| T-Spin Mini Single | 1 |
| T-Spin Single | 2 |
| T-Spin Double | 4 |
| T-Spin Triple | 6 |
| B2B 修正 | 攻击值 ×1.5（向上取整） |
| Combo 加成 | 第 2 连起每连 +1，上限 +5 |
| Perfect Clear | +10 |

垃圾行规则：
1. 每行恰有 1 个随机洞，**同一批次的洞在同一列**
2. 玩家产生的攻击**先抵消（offset）自己待接收（pending）的垃圾行**，1:1 抵消，剩余才转发给对手（生存模式发给其他存活对手；限时赛同）
3. 待接收垃圾显示为对手板下方的**红色预警条**（数量可视化）
4. 攻击发出后有 **500ms 缓冲**，之后整批插入接收者棋盘底部，棋盘整体上移
5. 单批插入上限 8 行，超出部分留在队列下批插入

### 4.4 三模式规格
| 维度 | A. sprint 竞速赛 | B. survival 生存淘汰 | C. timed 限时赛 |
|---|---|---|---|
| 核心目标 | 最先清满 N 行者胜 | 最后存活者胜 | 时长结束总分最高者胜 |
| 攻击/垃圾行 | ❌ 关闭，各自独立棋盘 | ✅ §4.3 全量规则 | ✅ §4.3 全量规则 |
| 顶出后果 | 棋盘重置继续冲线（已清行数保留） | **淘汰** → 转为观战（可聊天） | 3 秒倒计时复活：棋盘清空、**分数与消行数保留**、复活后 3 秒免伤 |
| 结束条件 | 全员完赛 或 300s 超时 | 仅剩 1 名存活者，或剩余全员同时顶出 | 计时归零（所有客户端以服务器 tick 为准） |
| 完赛/排名依据 | 完赛时间升序；未完赛者按已清行数降序 | 淘汰顺序倒序（最后存活第 1） | 总分 → 消行数 → 顶出次数 |
| 平局 | 同一 tick 内完赛 → 并列 | 剩余多人同时顶出 → 并列第 1 | 同分同消行同顶出 → 并列 |
| 可调参数 | `targetLines`：20 / 40（默认 40）；超时固定 300s（不可调） | 无 | `timeLimit`：120 / 180 / 300s（默认 180）；`respawnDelay` 固定 3s（常量，不可调） |
| 主要 HUD | 个人进度 `n/40` + 全员进度条 | 存活人数、攻击预警条、威胁指示 | 剩余时间 + 实时排名 + 复活倒计时 |

### 4.5 复活 / 淘汰补充规则
- 淘汰玩家保留在房间座位列表，标记「已淘汰」，仍可聊天与观战所有人棋盘；不参与存活人数计算
- survival 模式：仅剩 1 人存活时，其余观战者可看到胜利结算；所有人同时顶出 → 并列
- timed 模式复活期间：不产生攻击、不接收攻击（免伤 3s），倒计时显示在自己板上方
- sprint 模式顶出：棋盘清空重来，消行计数保留（防负反馈死局）

## 5. 功能需求（FR）

> 每条含验收标准（AC），编号供 `test-plan.md` 验收矩阵追溯。

### FR-1 访客身份与大厅
- FR-1.1 首次进入自动生成访客身份：UUID `playerId` + 默认昵称「玩家_四位随机」，持久化 localStorage
  - AC1：刷新页面身份不变；AC2：清除 localStorage 后生成新身份；AC3：昵称中 HTML 特殊字符按纯文本显示
- FR-1.2 昵称可修改：≤12 字符、去首尾空格、非空；同房间内重复昵称自动加后缀
- FR-1.3 大厅提供：单人模式 / 创建房间 / 房间码加入 / 快速匹配 / 设置 五个入口

### FR-2 房间
- FR-2.1 房间码：6 位（去除 0/O/1/I 的字符集），冲突重试；创建时选「公开（可被快速匹配）/ 私密」
- FR-2.2 容量 4 席（含 AI）；列表显示昵称、类型（真人/AI/空位）、准备状态、在线状态
- FR-2.3 房主权限（仅 WAITING 生效）：修改模式与参数、补 AI（1-3）、移除玩家、开局；房主离开/断线超时自动转让给最早加入者
- FR-2.4 非房主：准备/取消准备、离开
- FR-2.5 开局条件：≥2 个座位被占用（真人或 AI）**且所有真人玩家已 ready（房主默认视为已准备）**；COUNTDOWN 3 秒后进入 PLAYING
- FR-2.6 模式参数：sprint `targetLines` ∈ {20, 40}（默认 40）；timed `timeLimit` ∈ {120, 180, 300}s（默认 180）；survival 无参数
- AC：全部权限与状态转换有 TC-ROOM-001~005 覆盖

### FR-3 单人模式
- FR-3.1 Marathon：无限模式，按 §4.1 升级与 §4.2 计分，顶出结束显示成绩
- FR-3.2 Sprint 40：清 40 行计时，成绩写入 localStorage 最佳纪录
- FR-3.3 单人可暂停（Esc），暂停时重力与锁定延迟冻结；多人模式无暂停（见 FR-12）
- AC：TC-UI-002/003

### FR-4 AI 对战
- FR-4.1 难度 EASY / NORMAL / HARD：以「落点评估质量 + 思考延迟 + 误操作率」区分
- FR-4.2 AI 运行于服务端，与真人共用 `shared/engine` 与同一输入通道
- FR-4.3 WAITING 阶段可补位/移除 AI；真人加入可替换 AI 座位
- AC：TC-BOT-001/002；EASY 与 HARD 固定 seed 下 100 局胜率差异显著

### FR-5 核心操作与手感
- FR-5.1 §4.1 全部机制（SRS/7-bag/Hold/Next×5/Ghost/锁定延迟/DAS/ARR）
- FR-5.2 默认键位：←/→ 移动，↑ 或 X 顺时针，Z 或 Ctrl 逆时针，↓ 软降，Space 硬降，Shift 或 C Hold，Esc 面板；支持改键并持久化
- AC：TC-ENG-001~008、TC-UI-010

### FR-6 模式 B：survival 生存淘汰
- §4.3 攻击系统全量启用；淘汰者转观战（可聊天）；HUD 显示存活人数与攻击预警条
- AC：TC-MD-B-001~004、TC-UI-006

### FR-7 模式 C：timed 限时赛
- 服务器 tick 计时；顶出 3s 复活（棋盘清空、分数保留、3s 免伤）；结束按 §4.4 排名
- AC：TC-MD-C-001~003、TC-UI-007

### FR-8 模式 A：sprint 竞速赛
- 无攻击；进度 `n/{targetLines}` HUD（targetLines 为本局设置值，非固定 40）；完赛即定格时间；300s 超时按已清行数排名
- AC：TC-MD-A-001~004、TC-UI-005

### FR-9 聊天
- FR-9.1 房间级纯文本：≤200 字符，限流 1 条/s 且 10 条/10s（超出 E4290）
- FR-9.2 系统消息（加入/离开/被踢/淘汰/复活/胜负）以独立样式显示，i18n key 渲染
- FR-9.3 安全：服务端清洗控制字符；客户端 React 文本节点渲染，禁用 `dangerouslySetInnerHTML`
- FR-9.4 Enter 聚焦/发送，Esc 退出输入框（避免与游戏键冲突）；消息不落库
- AC：TC-CHAT-001~003、TC-UI-008、TC-SEC-002

### FR-10 断线与重连
- FR-10.1 心跳 15s，30s 无响应判定断线；断网客户端显示「重连中」遮罩
- FR-10.2 30s 宽限：resumeToken 恢复座位与棋局（下发全量态）；宽限期棋盘冻结、不收发攻击
- FR-10.3 宽限超时：survival 判淘汰 / timed 计一次顶出并继续复活循环 / sprint 移出排名；房主超时转让
- AC：TC-NET-003/004、TC-UI-009、TC-NET-101~104

### FR-11 界面
- FR-11.1 五屏：大厅 / 房间 / 游戏 / 结算 / 设置
- FR-11.2 游戏屏：己方大板 + ≤3 对手小板（昵称、分数或行数、状态、攻击预警）+ 聊天侧栏（可折叠）；HUD 随模式切换（§4.4）
- FR-11.3 结算屏：排名表（模式相关字段）+「再来一局」（回 WAITING，设置保留）
- AC：TC-UI-004~007/011、TC-COMPAT-002

### FR-12 设置与输入
- FR-12.1 设置项：音效/音乐音量、DAS/ARR、改键、Ghost 开关、色盲模式；持久化 localStorage
- FR-12.2 多人模式下 Esc 仅打开设置面板，游戏不暂停；单人可暂停（FR-3.3）
- FR-12.3 （P2，可延后至 M6）移动端触控：虚拟按键 + 滑动手势
- AC：TC-UI-010、TC-ACC-002

## 6. 非功能需求（NFR）
- **NFR-1 性能**：同区域 RTT≤50ms 下输入权威收敛 p95 < 100ms（TC-PERF-002）；客户端 60FPS（TC-PERF-004）；单进程 ≥200 房间 / 800 连接，内存 < 300MB@200 房（TC-PERF-003）；首屏 < 1.5s
- **NFR-2 兼容**：Chrome/Edge/Firefox/Safari 最近 2 大版本；1366×768 ~ 4K 自适应（TC-COMPAT-001/002）
- **NFR-3 安全**：服务端权威（TC-SEC-001）；Zod 全量校验 + 4KB 消息上限（TC-SEC-003）；聊天纯文本防 XSS（TC-SEC-002）；限流（TC-CHAT-001、TC-SEC-004/007）；Origin 校验（TC-SEC-005）；resumeToken 不可伪造（TC-SEC-006）；无 PII 持久化
- **NFR-4 可用性**：进程异常退出以非零码退出，交由 Docker/systemd 重启；优雅停机广播 E4999
- **NFR-5 可访问性**：色盲配色方案（TC-ACC-001）；关键信息不单靠颜色；全键盘可操作
- **NFR-6 可观测性**：结构化 JSON 日志（房间/座位/事件）；`/healthz` 存活探针；连接数/房间数简易指标
- **NFR-7 部署**：单 Docker 镜像（node:22-alpine）；WSS 经反代终止；全部配置走环境变量（PORT、ORIGIN、ROOM_TTL…）

## 7. 数据与状态
- 服务端全部内存态，**进程重启即全部房间丢失**（已向用户明确并接受）
- 客户端 localStorage 仅存：`playerId`、昵称、设置、单人最佳成绩
- 无数据库、无 Redis（ADR-0001）；预留 `RoomStore` 接口以备未来扩展

## 8. 约束与风险
| 编号 | 风险 | 缓解 |
|---|---|---|
| R1 | 反向代理下 WebSocket 升级/超时问题 | 反代配置章节（技术设计 §9）+ WSS |
| R2 | 脚本级自动化输入作弊 | 输入限流 60/s；接受为规则内风险 |
| R3 | 恶意刷房/刷连接 | IP 级限流（protocol §9） |
| R4 | 客户端时钟漂移影响 timed 模式 | 全部以服务器 tick 为准，客户端仅显示 |
| R5 | 浏览器后台节流（切标签页掉帧） | 权威逻辑在服务器；客户端仅渲染 |
| R6 | 断线宽限期内的公平性 | 冻结策略 + 超时判负（FR-10.3） |
| R7 | AI 强度不可控（过强/过弱） | 固定 seed 批量对局回归（TC-BOT-001） |

## 10. 术语表
| 术语 | 含义 |
|---|---|
| SRS | Super Rotation System，标准旋转系统（含踢墙表） |
| 7-bag | 每袋装 7 种方块洗牌后依次取出的随机算法 |
| Hold | 暂存当前方块换取下一块 |
| Ghost | 当前方块落点投影 |
| DAS / ARR | 延迟自动移位 / 自动重复速率（左右键手感参数） |
| Lock delay | 方块触底后允许移动的宽限时间 |
| T-Spin / Mini | T 块旋转入位的特殊消行判定 |
| B2B | Back-to-Back，连续高难消行加成 |
| Combo | 连续锁定均有消行的连击 |
| PC | Perfect Clear，清空整个棋盘 |
| 垃圾行 / 攻击 | 对战机制：使对手棋盘底部升起带洞的行 |
| 顶出（Top-out） | Block Out 或 Lock Out，棋盘溢出 |
| offset / 抵消 | 用自己的消行攻击抵消待接收垃圾行 |
| sprint | 40 行竞速模式 |
| seed | 随机序列种子，保证可复现 |
