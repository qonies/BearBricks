# ADR-0002：服务端权威 + 客户端乐观渲染

- 状态：已接受（2026-10-22）
- 关联：protocol.md、technical-design.md §4

## 决策
服务器是唯一权威：
- 客户端输入（左/右/旋转/软降/硬降/Hold）**立即在本地乐观应用并渲染**（零手感延迟），同时带自增 `seq` 上行
- 服务器 60Hz 固定步长 tick，按 `seq` 序应用输入，运行 `shared/engine`
- 下行：己方权威快照 **20Hz** + 输入回执；对手棋盘 **10Hz**，仅变化时发送（压缩编码）
- 客户端比较权威快照与本地预测状态，不一致时校正（通常仅在丢包/限流时发生）

## 理由
- 纯客户端权威实现最简单但作弊零门槛（改内存=改分数）；纯服务器渲染延迟不可接受
- 俄罗斯方块输入为离散事件、无持续物理碰撞预测，乐观渲染的回滚成本极低，天然适合此混合模型
- 60Hz 固定步长保证确定性：同一 seed + 同一输入序列 = 同一结果（可测试、可回放调试）

## 备选
| 备选 | 不选原因 |
|---|---|
| 客户端权威 | 作弊零成本，无法做公平对战 |
| 锁步（lockstep） | 一个丢包全场卡顿，公网体验差 |
| 纯服务器渲染+输入转发 | 输入延迟 = RTT，手感崩坏 |

## 后果
- 需处理：seq 基线（TCP 不乱序，但重连后以全量快照的 `seq` 为确认基线、**不重置**，重放未确认输入）、快照版本对齐（带 tick 号）、限流时的校正抖动（插值/直接覆盖策略）
- 后台浏览器节流不影响权威结果（计时以服务器 tick 为准，需求风险 R5）
